Key highlights of my career

Druva

Senior Staff Software Engineer in the Foundation Daintree team, responsible for designing and developing the storage control plane. Daintree is Druva's cloud file system built on S3 and DynamoDB, supporting object stores like AWS S3 and Azure Blob Storage. Built the orchestration system to migrate data from the older DRST file system to Daintree.

Daintree Migration

Daintree is cloud file system built on top of custom LSM database using S3, DDB. With majority of metadata stored on S3, it provides less OPEX compared to older file system which was using only DDB leading to high DDB storage and IO cost.

Daintree Migration aims to migrate metadata from older file system to Daintree architecture to enable cost reduction as well as allow supporting direct S3 data uploads.

Designed and developed message based orchestration platform using SQS. The system aims to migrate nearly all 5M+ devices to new Daintree architecture.

Designed cleanup workflow to delete DDB metadata from older file system once the device is successfully migrated to Daintree. Extended the orchestration system to support workload batching, parallel cleanups to optimize DDB IOPS usage.

HAProxy Service Controller

Led the effort to develop custom HAProxy Runtime API based controller which is responsible for dynamically managing both control and data plane nodes based on ASG events with periodic reconciliation.

As traffic increased we supported both Layer 4 and Layer 7 HAProxy to allow customer to only whitelist subset of IPs instead of entire AWS. Contributed in design of horizontal scaling to support 7x traffic growth.

Solved several issues around draining nodes, node reconciliation, critical cross deployment issues leading to incorrect routing of traffic to another deployment.

Control @ Master Plane

Daintree is deployed as per regional deployment. This provides an isolation across region but it also followed 80:20 rule as with life, 80% of traffic concentrated on few regions and other regions did brought a lot of dead weight cost of simply running these services 24x7.

Contributed in several efforts to streamline and support single control plane with key efforts in job system, index changes.

Batch Schedular

Daintree File System has strict SLA requirement to run periodic background jobs such as snapshot expiry, compaction, data tier movement, integrity checks (fsck) to delete expired snapshots and also monitor file system health. These stricter SLAs are defined to ensure customer does not overpay for backup storage.

Designed a simpler schedular aim to deprecate and replace older queuing schedular directly using DynamoDB index as virtual index to track SLAs.

Quarantine Bay

In case of ransomware attack, attacker infects customer backup with malicious files or corrupt them, as these are continuously backed up snapshots post attack are infected too. Quarantine Bay is feature to isolate infected snapshots and many cases create a clean snapshot from multiple snapshot to avoid data loss.

Worked on file system changes to store quarantine ranges, detection of latest cleanup snapshot. Designed latest snapshot detection and prevented it getting deleted in snapshot expiry or compaction workflow.

Developed session refresher middleware to automatically refresh OAUTH tokens while creating cleanup snapshot in product workflow with dedicated session support.

Persistent System Ltd

Worked on Blue Dart project, to develop new shipping platform with main goal to transition from monolith .NET PL/SQL to service oriented architecture with high availability without disrupting operations.

Link Paperwork Feature

All major banks partner with Blue Dart to courier letters, envelopes. These types of courier are very large in number, smaller in size but very high priority with requirement to get them delivered in 1-2 working days.

Developed paperwork feature to optimize managing and delivery of these type of parcels by bagging them into single unit depending on the transit and final destination.

Integrated third party shipping solution to delivery high priority parcels, leverages Async Java to fetch delivery rates to reduce latency of each bag operation.

Created common framework to support Recursive CTEs in our custom Hibernate adapter which was critical to determining courier routes and bagging eligibility.

Reporting Framework

All major operations in Blue Dart rely on dozen+ columns reports, to understand volume as well as reconcile parcels processed by them. These reports are generated on demand, daily depending on the operation.

Optimized common reporting engine to support 24+ columns, developed a lot of jasper reports.
